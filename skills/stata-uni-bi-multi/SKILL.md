# Stata 单变量、双变量、多变量分析

对一个二分类因变量依次做三步分析：单变量（描述统计）、双变量（t 检验与卡方检验）、多变量（logistic 回归，报告 OR）。全部命令写进一个 do 文件，由 Stata 执行，结果从日志读回，写入用户指定的 Markdown 文件。

do 文件一律由 `assets/analysis-template.do` 生成，**只改文件头日期和参数区**。检验方法、样本限定、输出格式都已写定在模板里，不因数据或结果而改动；这样同一套规则每次都按同样的方式执行，看到结果之后也不会再去换检验。

## 适用与不适用

- 适用：因变量在分析样本中只取 0 和 1；自变量由用户分为连续、分类两类。
- 不适用：因变量为连续、计数或多分类变量；需要抽样权数（svy）、面板或多层模型。遇到这些情况，停下说明本技能不适用，不自行改用别的模型。
- 用户没有要求的分析一律不做，包括边际效应、交互项、模型比较、稳健性检验、导出 Word、作图。用户明确要求时，按 `references/optional-modules.md` 做。

## 一、确认参数

| 参数 | 含义 | 例 | 缺省 |
| --- | --- | --- | --- |
| `data` | 数据文件，相对项目根目录 | `inputs/clhls2021_analysis.dta` | 必填 |
| `y` | 因变量，0/1 | `disabled` | 必填 |
| `xcont` | 连续自变量 | `age edu` | 可空 |
| `xcat` | 分类自变量；改参照组写 `ib#.变量名` | `female urban a51` | 可空 |
| `flag` | 分析样本标记变量名 | `analysis` | `analysis` |
| `savedata` | 1＝把标记变量存回数据文件 | 1 | 0 |
| do 文件位置 | 命令保存在哪里 | `do/analysis.do` | `do/analysis.do` |
| 结果文件与标题 | 结果写入哪个 md、用什么标题 | `CLHLS2021-ADL失能影响因素分析.md`，“五、数据分析结果” | `results/analysis-results.md`，“数据分析结果” |

- 必填项缺失时，一次列出所缺各项再问，不猜。`xcont` 与 `xcat` 不能同时为空。
- 变量类型以用户的划分为准，不自行改划。用户没有划分时，先只看不改地查看数据（`describe`、`tabulate`，或连接器的 `get_data_info`），按取值个数与值标签提出划分建议，经用户确认后再运行。
- 用户明确说“可以修改数据库”或“可以修改数据文件”时，`savedata` 才设为 1；否则为 0，标记变量每次运行时重新生成。
- 分类变量默认以取值最小的类别为参照组。用户指定其他参照组时，在 `xcat` 里写 `ib#.变量名`，如 `ib2.a51`。

## 二、检查环境

1. **执行方式**，按顺序选用：
   - **Stata 连接器（stata-mcp）**：用 `stata_do` 执行 do 文件，用 `read_log` 读日志。日志由连接器自动保存（通常在项目下的 `.statamcp/stata-mcp-log/`），所以 do 文件里不写 `log using`。项目路径须为全英文；路径含中文时，连接器回传结果会报编码错误，应提醒用户把项目复制到英文路径下再做。
   - **命令行批处理**：在项目根目录执行，日志生成在当前目录，与 do 文件同名（`analysis.log`）。
     - macOS：`/Applications/Stata/StataSE.app/Contents/MacOS/stata-se -b do do/analysis.do`。MP、BE 版把 `StataSE`、`stata-se` 换成相应名称；可用 `ls /Applications/Stata*/*.app/Contents/MacOS/` 查找。
     - Windows：`"C:\Program Files\Stata18\StataSE-64.exe" /e do do\analysis.do`，按实际版本与安装位置改写。
     - Linux：`/usr/local/stata18/stata-se -b do do/analysis.do`。
   - **两者都没有**：只写 do 文件，请用户在 Stata 中运行，再把日志交回。不得编造或估计结果。
2. 核心三步只用 Stata 自带命令（`summarize`、`tabulate`、`ttest`、`logit`、`markout`），不需要安装外部命令包。模板在 Stata 16 上实测通过，更早的版本未测试。

## 三、生成 do 文件

1. 把 `assets/analysis-template.do` 复制到 do 文件位置。同名文件已存在时，先复制一份备份，文件名后加 `.bak`。
2. 只改两处：文件头的日期；参数区的 `data`、`y`、`xcont`、`xcat`、`flag`、`savedata`。其余各段一字不改。
3. 改完核对：参数区的变量名与用户所给逐个一致；`savedata` 与用户的授权一致。

模板各段依次为：（一）读入数据与检查；（二）单变量分析；（三）双变量分析；（四）多变量分析；（五）结果汇总。第（一）段先检查参数与变量，再生成标记变量，然后在分析样本内检查因变量与分类变量的编码：

```stata
generate byte analysis = 1
markout analysis disabled age edu female urban a51   // 与 !missing(…) 等价
```

此后每条分析命令都带 `if analysis == 1`，任何观测都不删除。

## 四、运行与排错

1. 运行后先查错。**判断是否出错只看日志**：日志里出现 `r(数字);` 的行即为出错。命令行批处理即使出错，退出码也可能是 0。
2. 模板对常见问题给出中文提示：

| 日志中的错误 | 原因 | 处理 |
| --- | --- | --- |
| r(601) | 数据文件不存在 | 核对工作目录与 `data` 路径 |
| r(111) | 变量不存在 | 核对变量名（模板关闭了变量名缩写匹配，须写全） |
| r(7) | 有字符串变量 | 请用户先把该变量编码为数值 |
| r(198) | 参数矛盾：未列自变量、同一变量列入两类、因变量作自变量 | 改参数 |
| r(459) | 因变量不是 0/1，或只有一个取值；分类变量含负数或小数 | 停下说明，请用户处理数据 |

3. 不得为了跑通而改动模板的分析各段，不得删除观测、更换检验方法或模型。同一错误修改两次仍未解决，停下报告错误原文。

## 五、读结果

1. 写结果用的数字一律取自日志末尾“结果汇总”段的【……】行，并与前面各命令的完整输出对照。不估算、不手算、不凭记忆补数。
2. 写之前核对三项：
   - **样本量前后一致**：`【样本】`的分析样本、各分类变量频数之和、t 检验两组之和、`【多变量-模型】`的 N。
   - **logistic 回归的提示**：日志中有 `predicts success perfectly`、`predicts failure perfectly`、`omitted`、`not concave`、`convergence not achieved`，或汇总段出现“注意：logit 实际使用……”“无观测进入回归”“被略去”时，必须写进结果说明，相关变量的 OR 不作解读，并提示用户考虑合并类别；不得自行合并。
   - **卡方检验的“报告：”字段**：最小期望频数小于 5 的变量，报告 Fisher 精确检验的 p 值，并在表注中说明。

## 六、写结果文件

1. 按 `references/report-template.md` 写：样本说明、表 1 至表 5、表注。
2. 结果文件已存在时，先备份，再把本节追加在文末，即用户所说的上一项任务结果之后。文件中已有同名标题时，替换该节内容，不重复追加。
3. 只写汇总统计量，不写任何个体记录。
4. 默认只给表格与表注。用户要求文字说明时，只复述表中数字，用“与……相关”“发生比是……的 X 倍”等措辞，不写“导致”“影响了”这类因果判断。

## 七、交付前自检

- [ ] do 文件由模板生成，只改了日期与参数区。
- [ ] 每条分析命令都带 `if analysis == 1`（或所设的标记名），没有删除观测的 `drop`、`keep`。
- [ ] 连续变量报告均值、标准差；分类变量报告频数、百分比。
- [ ] 连续自变量用 t 检验，分类自变量用卡方检验；期望频数小于 5 的改报 Fisher 精确检验。
- [ ] logistic 回归报告 OR、95% 置信区间、p 值与样本量；分类自变量以 `i.` 进入，参照组在表中写明。
- [ ] 结果文件中的每个数字都能在日志里找到；样本量前后一致。
- [ ] 没有做用户未要求的分析；只在用户允许时修改了数据文件。
- [ ] 改写已有文件前做了备份。

## 文件

- `assets/analysis-template.do`：do 文件模板。
- `references/report-template.md`：结果文件的写法与表格样式。
- `references/optional-modules.md`：可选模块，包括 OR 表导出、OR 图、稳健性检验，只在用户明确要求时使用。
